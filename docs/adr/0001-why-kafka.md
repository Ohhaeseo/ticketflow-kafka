# ADR-0001: 예약 처리에 Kafka를 도입하는 이유

- **상태:** 제안됨 (1주차 일요일 11/29 확정 예정)
- **날짜:** 2026-11-20

## 맥락

- 잔여 100장에 1,000명이 동시에 예약을 시도하면 요청이 짧은 시간에 몰린다.
- 요청마다 동기적으로 재고를 감소시키면 같은 행에 잠금 경합이 집중되고, 응답 지연이 요청자 전체로 퍼진다.
- 초과 판매 방지는 어떤 방식을 택하든 DB 원자적 갱신으로 보장해야 한다.

## 검토한 대안

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| 동기 DB 처리 (조건부 UPDATE) | 단순, 즉시 결과 | 피크 시 잠금 경합과 지연이 요청자에게 직접 전달 |
| Redis 큐 / 원자 연산 | 빠름 | 영속성·재처리 보장을 별도 설계해야 함 |
| RabbitMQ 등 다른 브로커 | | |
| Kafka + Outbox | 완충, 재소비, Consumer 확장, 장애 복구 | 운영 복잡도, 최종 결과까지 지연, 멱등 처리 필수 |
